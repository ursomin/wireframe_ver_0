# 생활체육 모임 플랫폼 PRD

> 문서 상태: 정적 프로토타입 기준 초안
>
> 작성일: 2026-08-09
>
> 프로젝트명: PLAYUPP(가칭, 순우리말 서비스명으로 변경 예정)
>
> 현재 구현 범위: HTML, CSS, JavaScript 및 브라우저 `localStorage`만 사용하는 화면 설계용 프로토타입

## 1. 제품 개요

사용자가 거주 지역과 운동 종목, 일정, 실력 수준에 맞는 생활체육 모임을 찾거나 직접 만들고, 운동 전후의 관계를 지속할 수 있도록 돕는 지역 기반 운동 모임 플랫폼이다.

단순히 참가자를 모집하는 데서 끝나지 않고 다음 경험을 하나의 흐름으로 연결한다.

1. 조건에 맞는 모임 탐색
2. 참가 신청 또는 빠른 매칭
3. 모임방과 채팅을 통한 사전 소통
4. 출석 및 운동 완료 처리
5. 상호 실력 평가
6. 완료된 모임 채팅방을 통한 재모임과 친구 관계 유지

## 2. 문제 정의

생활체육 참여자는 다음과 같은 문제를 겪는다.

- 주변에서 원하는 종목을 함께할 사람을 찾기 어렵다.
- 같은 초급자라도 실제 실력 차이가 커 모임 만족도가 떨어질 수 있다.
- 참가 신청 후 승인 여부와 현재 상태를 확인하기 번거롭다.
- 노쇼, 당일 취소, 비매너 사용자로 인한 운영 부담이 크다.
- 운동이 끝나면 기존 참여자와 다시 연결되기 어렵다.
- 기존 서비스에서는 신고, 차단, 출석 이력과 같은 신뢰 장치가 부족하거나 과도하게 공개된다.

## 3. 제품 목표

### 3.1 핵심 목표

- 사용자가 자신에게 맞는 운동 모임을 빠르게 찾고 참가할 수 있게 한다.
- 모임장이 참가 신청과 참여자를 한곳에서 관리할 수 있게 한다.
- 실력 수준과 참여율을 활용해 모임 선택의 불확실성을 줄인다.
- 운동 완료 후에도 채팅방과 친구 기능을 통해 관계가 이어지게 한다.
- 사용자 차단과 신고 기능으로 안전한 매칭 환경을 제공한다.

### 3.2 비목표

초기 제품에서는 다음 기능을 핵심 범위에 포함하지 않는다.

- 대회 및 리그 운영
- 전문 코치 예약
- 운동 시설 결제 및 정산 대행
- 운동 기록 측정 또는 웨어러블 연동
- 공개 랭킹이나 경쟁형 매너 점수

## 4. 대상 사용자

### 4.1 일반 참여자

- 가까운 지역에서 가볍게 운동할 사람을 찾고 싶은 사용자
- 자신의 실력에 맞는 모임에 참여하고 싶은 입문자 및 생활체육인
- 과거에 함께 운동한 사람과 다시 운동하거나 친구가 되고 싶은 사용자

### 4.2 모임장

- 운동 일정과 장소를 정해 참가자를 모집하는 사용자
- 참가 승인, 출석, 참여자 관리가 필요한 사용자
- 노쇼나 부적절한 사용자를 신고 또는 강퇴해야 하는 사용자

### 4.3 운영자

- 사용자와 모임을 관리하는 서비스 운영 담당자
- 신고 내용을 검토하고 필요한 조치를 수행하는 관리자

## 5. 제품 원칙

- 매칭 조건은 단순하고 이해하기 쉬워야 한다.
- 공개 정보와 본인만 볼 수 있는 민감한 정보를 명확히 구분한다.
- 운동이 끝나도 유용한 관계와 대화는 유지한다.
- 차단된 사용자끼리는 다시 연결되지 않도록 한다.
- 실력 평가는 처벌이 아니라 적절한 모임 선택을 돕는 정보로 사용한다.
- 현재 프로토타입의 모든 데이터와 동작은 실제 서비스가 아닌 화면 검증용임을 전제로 한다.

## 7. 핵심 사용자 흐름

### 7.1 모임 참가

1. 사용자가 홈에서 종목, 지역, 날짜, 시간대, 실력 수준 등을 선택한다.
2. 검색 결과에서 모임을 선택해 상세 정보를 확인한다.
3. 참가 신청을 누른다.
4. 빠른 매칭 모임은 즉시 참여 확정된다.
5. 승인 필수 모임은 승인 대기 상태가 된다.
6. 확정된 모임은 `내 모임 > 참여 중인 모임`과 모임톡에서 확인한다.

### 7.2 모임 생성 및 운영

1. 사용자가 모임 생성 화면에서 필수 정보를 입력한다.
2. 빠른 매칭 또는 모임장 승인 필수 방식을 선택한다.
3. 생성된 모임은 `내 모임 > 내가 만든 모임` 상단에 노출된다.
4. 모임장은 모임방 관리 페이지에서 참가 신청을 승인하거나 거절한다.
5. 모임장은 참여자 프로필을 확인하고 필요한 경우 강퇴한다.
6. 참가자와 모임장은 모임톡에서 운동 전후로 소통한다.

### 7.3 운동 완료 후 관계 유지

1. 운동이 끝나면 모임을 완료 상태로 전환한다.
2. 참여자는 함께 운동한 사용자의 실력을 상호 평가한다.
3. 완료된 모임은 `내 모임 > 참여했던 모임` 하단에 보관된다.
4. 완료된 모임톡은 삭제되지 않고 계속 접근할 수 있다.
5. 사용자는 참여자 프로필에서 원하는 사람에게만 친구 요청을 보낼 수 있다.

## 8. 기능 요구사항

### 8.1 회원 및 온보딩

- 사용자는 회원가입 및 로그인 화면을 이용할 수 있어야 한다.
- 최초 가입 시 관심 운동, 활동 지역, 종목별 실력 수준을 설정할 수 있어야 한다.
- 프로필 정보는 이후 수정할 수 있어야 한다.
- 정식 서비스에서는 인증과 권한 검사를 서버에서 수행해야 한다.

### 8.2 모임 탐색

- 키워드로 모임명, 종목, 지역을 검색할 수 있어야 한다.
- 종목, 지역, 날짜, 시간대, 실력 수준, 모집 상태, 참가비를 필터링할 수 있어야 한다.
- 거리순, 최신순, 남은 자리순 등으로 정렬할 수 있어야 한다.
- 원하는 모임을 찜하거나 찜을 해제할 수 있어야 한다.
- 차단한 사용자가 만든 모임은 검색과 추천에서 제외해야 한다.

### 8.3 모임 상세 및 참가

- 종목, 제목, 소개, 일정, 장소, 참가비, 실력 범위, 현재 인원, 모집 인원을 표시해야 한다.
- 모임장과 참여자 프로필로 이동할 수 있어야 한다.
- 참가 신청과 신청 취소가 가능해야 한다.
- 모임의 승인 방식과 현재 신청 상태를 명확히 표시해야 한다.
- 부적절한 모임을 신고할 수 있어야 한다.

### 8.4 모임 생성

- 모임 제목, 한 줄 소개, 종목, 날짜, 시작·종료 시간, 지역, 상세 장소를 입력받아야 한다.
- 모집 인원, 참가비, 최소·최대 실력 수준을 설정할 수 있어야 한다.
- 종료 시간은 시작 시간보다 늦어야 한다.
- 최소 실력은 최대 실력보다 높을 수 없다.
- 다음 승인 방식 중 하나를 선택해야 한다.
  - 빠른 매칭: 모임장 승인 없이 신청 즉시 참여 확정
  - 모임장 승인 필수: 모임장이 신청자의 프로필을 확인하고 승인 또는 거절

### 8.5 내 모임

- `내가 만든 모임`, `참여 중인 모임`, `참여했던 모임`을 구분해야 한다.
- 내가 만든 모임과 참여 중인 모임을 상단에 배치해야 한다.
- 운동이 종료된 참여했던 모임은 하단에 배치해야 한다.
- 참여 확정 모임과 완료 모임에서 모임톡으로 이동할 수 있어야 한다.
- 승인 대기 중인 신청은 취소할 수 있어야 한다.

### 8.6 모임방 관리

- 모임장은 대기 중인 참가 신청 수와 현재 참여자 수를 확인할 수 있어야 한다.
- 신청자의 프로필과 참여율을 확인한 후 승인 또는 거절할 수 있어야 한다.
- 승인하면 신청자가 현재 참여자 목록과 모임톡 인원에 반영되어야 한다.
- 참여자 프로필을 누르면 요약 정보와 프로필 전체 보기 기능을 제공해야 한다.
- 모임장에게만 참여자 강퇴 기능을 제공해야 한다.
- 강퇴된 사용자는 해당 모임과 모임톡에 더 이상 접근할 수 없어야 한다.
- 현재 예시 상태는 참가 신청자 `다현`, 참여자 `은아`, `규동`, 모임장 본인으로 구성한다.

### 8.7 채팅 및 친구

- 진행 중인 모임과 완료된 모임의 모임톡을 구분해 제공해야 한다.
- 운동 완료 후에도 모임톡을 유지해야 한다.
- 사용자는 채팅 참여자의 프로필을 확인할 수 있어야 한다.
- 사용자는 원하는 참여자에게 친구 요청을 보낼 수 있어야 한다.
- 친구와는 개인톡을 시작할 수 있어야 한다.
- 차단 관계에서는 새로운 개인 메시지를 주고받을 수 없어야 한다.
- 정식 서비스에서는 WebSocket 기반 실시간 메시징과 메시지 보관 정책이 필요하다.

### 8.8 실력 수준 및 상호 평가

종목별 실력 수준은 다음과 같이 단순하게 안내한다.

| 수준 | 설명                                                  |
| ---- | ----------------------------------------------------- |
| 입문 | 규칙과 기본 동작을 아직 잘 모르는 단계                |
| 초급 | 기본 규칙을 알고 간단한 게임에 참여할 수 있는 단계    |
| 중급 | 안정적으로 게임을 진행하고 전술을 활용할 수 있는 단계 |
| 고급 | 숙련된 기술과 경기 운영 능력을 갖춘 단계              |

운동 완료 후 함께 운동한 사람마다 다음 중 하나를 선택해 평가할 수 있어야 한다.

- 본인이 등록한 실력보다 낮다.
- 본인이 등록한 실력과 비슷하다.
- 본인이 등록한 실력보다 높다.

평가 결과는 개인의 공개 점수를 매기는 용도가 아니라 등록 실력의 정확도 개선과 적합한 모임 추천에 활용한다. 정식 서비스에서는 익명성, 최소 평가 수, 악의적 평가 방지 정책을 별도로 설계해야 한다.

### 8.9 참여율

- 내 프로필과 상대 프로필 모두 전체 참여율을 표시해야 한다.
- 상세 참여 이력은 본인 프로필에서만 본인에게 공개해야 한다.
- 상대 프로필에서는 전체 참여율만 표시하고 세부 횟수는 노출하지 않는다.

상세 참여율 항목은 다음과 같다.

| 항목        | 정의                             |
| ----------- | -------------------------------- |
| 전체 참가   | 참여가 확정된 전체 모임 수       |
| 정상 출석   | 정상적으로 출석한 모임 수        |
| 출석률      | 정상 출석 ÷ 출석 대상 모임 × 100 |
| 당일 취소   | 운동 당일 참가를 취소한 횟수     |
| 노쇼        | 취소 없이 출석하지 않은 횟수     |
| 호스트 취소 | 모임장 사유로 취소된 횟수        |

호스트 취소는 참여자의 불참으로 계산하지 않으며 출석률의 분모에서도 제외한다.

### 8.10 차단 및 신고

- 상대 프로필에서 사용자를 차단하거나 차단 해제할 수 있어야 한다.
- 차단한 사용자와는 검색, 추천, 빠른 매칭, 모임 참가 및 개인톡에서 다시 연결되지 않아야 한다.
- 이미 같은 모임에 참여 중일 때 차단한 경우의 처리 정책은 정식 서비스 구현 전에 확정해야 한다.
- 사용자 프로필에서 사용자 신고가 가능해야 한다.
- 모임 상세에서 모임 신고가 가능해야 한다.
- 신고자는 대상, 사유, 상세 내용을 입력하고 접수 결과를 확인할 수 있어야 한다.
- 운영자는 관리자 신고 목록에서 신고 상태를 확인하고 처리할 수 있어야 한다.

### 8.11 커뮤니티 및 공지사항

- 상단 내비게이션에서 커뮤니티로 이동할 수 있어야 한다.
- 전체 글 목록은 제목 중심으로 표시하고, 사용자가 제목을 눌러야 본문이 열려야 한다.
- 게시판 필터와 글 검색을 제공해야 한다.
- 사용자는 새 글을 작성할 수 있어야 한다.
- 홈페이지 상단 공지 배너를 누르면 공지사항 페이지로 이동해야 한다.
- 초기 공지 예시는 `2026년 08월 09일 00:00 ~ 01:00 서비스 점검이 진행됩니다.`로 한다.

### 8.12 알림

- 참가 신청, 승인·거절, 일정 임박, 출석 및 평가 요청 등 주요 이벤트를 알려야 한다.
- 읽음 상태를 구분해야 한다.
- 알림을 누르면 관련 화면으로 이동해야 한다.

### 8.13 관리자

- 회원 목록 검색과 상태 관리를 제공해야 한다.
- 모임 목록 검색과 상태 관리를 제공해야 한다.
- 사용자 및 모임 신고를 한 목록에서 확인할 수 있어야 한다.
- 신고의 접수, 검토, 처리 완료 상태를 관리할 수 있어야 한다.
- 운동 종목과 운영 통계를 확인할 수 있어야 한다.
- 정식 서비스에서는 관리자 계정 인증과 역할별 권한 검증이 필수다.

## 11. 정적 프로토타입 범위

현재 버전은 서버와 데이터베이스 없이 화면 흐름을 검토하기 위한 프로토타입이다.

- HTML, CSS, JavaScript만 사용한다.
- 상태는 동일 브라우저의 `localStorage`에 저장한다.
- 브라우저 데이터를 삭제하면 모든 변경 상태가 초기화된다.
- 로그인과 권한은 실제 인증이 아닌 화면 시뮬레이션이다.
- 채팅, 신고, 승인, 출석, 평가는 실제 사용자나 운영 시스템으로 전송되지 않는다.
- 여러 사용자, 여러 기기, 여러 브라우저 사이에 데이터가 동기화되지 않는다.
- 현재 날짜와 모임 데이터는 사용자 흐름 확인을 위한 예시다.

## 12. 정식 서비스 전환 요구사항

### 12.1 서버 및 데이터

- 회원, 프로필, 종목별 실력, 모임, 신청, 출석, 채팅, 친구, 차단, 신고 데이터를 서버에 저장한다.
- 데이터 변경 이력과 관리자 처리 이력을 기록한다.
- 차단 관계를 모든 검색 및 매칭 쿼리에 적용한다.
- 강퇴와 승인 작업은 서버에서 권한을 검증하고 원자적으로 처리한다.

### 12.2 인증 및 보안

- 안전한 회원 인증과 세션 관리를 구현한다.
- 일반 사용자, 모임장, 관리자 권한을 서버에서 검증한다.
- 신고 및 상세 참여 기록 등 민감 정보에 접근 제어를 적용한다.
- 입력값 검증, 요청 제한, 감사 로그 및 개인정보 보호 정책을 마련한다.

### 12.3 실시간 기능

- WebSocket 기반 모임톡과 개인톡을 구현한다.
- 메시지 전송 상태, 읽음 상태, 재접속, 알림을 지원한다.
- 강퇴 또는 차단 시 채팅방 접근 권한을 즉시 갱신한다.

### 12.4 외부 연동

- 지도 및 체육시설 OpenAPI를 통한 장소 검색
- 푸시, 이메일 또는 SMS 알림
- 필요한 경우 소셜 로그인 및 본인 인증
